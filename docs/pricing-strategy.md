# 料金・獲得戦略（採用仕様）

2026-07-28 User決定。初回Google Play公開と将来のWeb契約を分離する。

## 結論：恒久無料枠 + 将来のWeb PRO

- 初回公開は、期間制限のない無料プラン。14日トライアル、自動有料化、自動課金は行わない。
- 無料でも登録時に1店舗の店舗コードと4桁PINを発行し、別端末ログインとルーム同期を利用できる。
- 将来のPROは月額2,980円の1本とし、Webで明示的に契約した店舗だけをPROにする。
- Google Play/TWA内では価格、Stripe、外部購入リンクを表示しない。Web契約済み店舗は同じ店舗コードでログインする。
- アプリ名は無料版/有料版に分けず、どちらも「タナオロ」とする。

## 無料枠

| 項目 | 無料版 | 将来のPRO |
|---|---:|---:|
| 店舗 | 1店舗（店舗コード1つ） | 初回は1店舗 |
| 同時接続端末 | 2台 | 上限緩和 |
| 登録品目 | 150件 | 上限緩和 |
| 棚卸履歴の閲覧 | 直近3回 | 全期間 |
| 棚卸・ルーム・手入力・音声入力 | 利用可 | 利用可 |
| 現行のCSV/PDF取込・書出し | 利用可 | 利用可 |

PROの具体的な最大値とfair-use上限は、Stripe提供開始前に負荷試験と利用状況を見て確定する。

## この形を採用する理由

- 無料利用者も2台同期まで体験でき、タナオロの中核価値を理解できる。
- 課金境界を基本機能の有無ではなく、端末数・品目数・履歴という運用規模に置ける。
- Playで無料登録できるため、検索から別サイトへ移動させるpaid-only型より離脱が少ない。
- 自動課金やトライアル終了時の機能喪失がなく、初回公開の説明と実装を単純にできる。

## 実装状況（2026-07-28）

- `planLimits.js` を2台・150品目・履歴3回へ更新し、本番で全員PRO扱いにしていた一時解除を撤去した。
- `tanaoro_is_pro` のlocalStorage自己申告ではPROにならない。初回公開のクライアントは全店舗を無料枠として扱う。
- Workerの14日トライアル算出を撤去した。API互換のため `inTrial:false` と `trialEndsAt:null` は残す。
- `stores.plan`（`free` / `pro`）は将来のサーバー判定用に維持する。
- アプリ内の旧1,980円、3か月無料、外部決済導線を撤去し、公開規約・サポート・landingを新仕様へ同期した。

## Stripe提供開始前に必要な実装

1. Stripe CheckoutはWebだけに置き、Webhookで`stores.plan`を更新する。
2. Appは認証APIが返すサーバー判定を使い、localStorageを権限の正にしない。
3. 端末・品目・履歴の上限をWorker/Durable Object側でも強制し、直接APIによる迂回を防ぐ。
4. 解約、支払失敗、猶予期間、account削除時の契約停止を実装する。
5. `0009_store_plan.sql`で既存店舗へ設定された`pro`値を、本番運用開始前に意図したプランへ整理する。
6. Webの特商法表示・利用規約・privacy・Data Safetyと、Google Playのconsumption-only導線を再監査する。
