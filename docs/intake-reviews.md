## 2026-07-15: 発注リアルタイム同期＋入出庫の未記録ドラフト（82f5100..0c15363・4コミット）

対象: 発注数の orders チャネル（Phase 1/2）・棚卸カード誤表示修正・入出庫の未記録保持＋バッジ
総評: **設計は既存パターンに忠実で良質**（サニタイズ・監査ログ・送信者除外・純関数分離・
テスト付き・storageKeys/accountData への登録も漏れなし）。以下の指摘のみ。

### 必須
- **R2-01 入出庫の既定日付が「前回入力日」のまま残る（日付の静かなズレ）**
  `useMovementDraft` が `date` を localStorage に永続化し、`_load()` は空のときだけ今日にする。
  `clearMode()` も date を触らないため、**翌日以降の入出庫の既定日付が前回操作日のまま**になる
  （従来はページ表示ごとに今日を初期値にしていた＝リグレッション）。
  入出庫の日付は理論在庫・営業日分析の入力なので、静かに狂うと分析が汚れる。
  修正案: ドラフトが空（draftCount===0）のとき date を今日へリセット（load時＋保存後）。

### 推奨
- ✅ **R2-02 出庫保存で入庫側の発注紐付け・メモが消える**（2026-07-17 `1fd0a8e` で修正済み）
  `clearMode(mode)` が保存モードに関係なく `orderId / orderLabel / note` をクリアする。
  再現: 発注を入庫へプリフィル → 出庫タブへ → 出庫を保存 → 入庫の数量は残るが
  紐付け(orderId)とメモが消える → その後の入庫保存が発注と紐付かない（発注→入庫の環の欠損）。
  修正案: orderId/orderLabel は `mode==='in'` の保存時のみクリア。note の扱いも同時に決める。
- **R2-03 発注数のオフライン動作が在庫と非対称（仕様未定義）**
  参加/再接続時は DO スナップショットが正で、ローカルのみの発注編集は黙って破棄。
  ホスト再接続でもローカル下書きを DO へ再送しない（在庫は3方向マージ＋再送）。
  低頻度だが「入れたはずの発注数が消えた」に直結。最低限仕様として明記（sync-spec に現状を
  記載済み）。望ましくは在庫と同様の updatedAt マージ＋再送へ。
- **R2-04 DO の order_update / order_remove にワーカー側テストがない**
  クライアント純関数（orderSync）はテスト済みだが、DO 側（サニタイズ・audit・
  session_start の orders 検証）が未カバー。RoomDO.config.test.js のパターンで追加を。

### 参考
- R2-05 `orderQty` に上限・有限チェックがない（`Infinity` は `typeof number` を通過し
  JSON 化で null になる）。在庫 update と共通の数値ガード（有限・上限・桁）を入れる余地。
- R2-06 DO storage の `orders` も単一キー保存（128KiB 上限の既知パターンの対象拡大。
  監査スケール節と同根・品目数上限の導入時に一緒に解決）。
- R2-07 `session_started` の orders スナップショット適用にセッション種別ガードがない
  （現状はセッション別 localStorage キーのおかげで実害なし。将来の変更に注意）。
