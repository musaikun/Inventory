# 長期戦略・設計原則（10年スパン）

最終更新: 2026-06-27
位置づけ: 機能の取捨選択・優先度判断の羅針盤。迷ったらここに戻る。

---

## 0. 一行で言うと

> **現場で在庫データが生まれる瞬間を押さえ、その記録の正（system of record）になり、
> AIの競合ではなくAIの手足になる。**

「単なる入力＋表示ツール」はAIに飲まれる。
「現場の捕捉＋記録＋判断の基盤」はAI普及で需要が増える。

---

## 1. 中核となる判断基準（“AIに飲まれるか” テスト）

新機能・既存機能を評価するとき、まずこれを問う：

> **「もしAIがすでにそのデータを持っていたら、我々はまだ必要か？」**

- **No → その機能は飲まれる**（計算・要約・きれいな表示だけ＝危険ゾーン）
- **Yes → 堀になる**（データを最初に捕捉する／保持する／多者をつなぐ＝安全ゾーン）

### 危険ゾーン（薄い差別化・いずれ汎用AIに代替される）
- 数字を打ち込んで合計・在庫金額を出すだけ
- 単なる表・グラフ表示
- 汎用的な計算・要約

### 安全ゾーン（積極的に投資する）
- 騒音の厨房で・手袋で・オフラインで・複数人並行で **速く物理量を捕捉**する最適化
- 時系列の独自データを **蓄積し続ける記録の正**
- 本部↔店舗↔仕入先の **多者ハブ**
- AIが **呼びに来る先**（MCP/API）になること

---

## 2. AIに飲まれないための4原則

1. **物理現実の捕捉点を押さえる** — 在庫データが最初に生まれる現場（厨房・バックヤード）を最適化する
2. **記録の正になる** — AIが参照・更新しに来る「店の在庫の記憶」を持つ
3. **AIの競合でなく手足になる** — MCP/API でAIエージェントから操作可能にし、「飲まれる」のでなく「呼ばれる」
4. **入力手段に依存しない** — 手入力・カメラ・センサー、捕捉手段が変わっても受け口になる（堀は中身＝記録と判断にある）

### 補足：本当の長期脅威は ChatGPT ではなく「自動センシング」
カメラ画像認識・RFID・スマート計量器が「数える行為」自体を自動化しうる。
対策は原則4＝**捕捉手段が何に変わっても取り込める記録・意思決定レイヤーであること**。

```
手入力 ──┐
カメラ ──┼─→ [記録・意思決定レイヤー（ここが堀）] ─→ 発注・最適化・仕入先連携
センサー ─┘
```

---

## 3. 4フェーズの成長ストーリー

各フェーズが次の土台になる。今の地味な作業（正確な記録・同期・履歴）はフェーズ3〜4の燃料。

```
フェーズ1（現在）  棚卸を速くする道具            ← 入口・データ収集の最適化
フェーズ2         本部×多店舗の在庫基盤          ← system of record 化（企業導入）
フェーズ3         AI発注・ロス検知・最適化        ← 意思決定レイヤー
フェーズ4         仕入先連携・取引決済            ← フィンテック化（最大の市場）
```

| フェーズ | 主価値 | 収益モデル |
|---|---|---|
| 1 | 棚卸の高速化・正確化 | 店舗サブスク（無料/PRO） |
| 2 | 多店舗の一元管理 | 企業契約（店舗数ベース） |
| 3 | 発注最適化・ロス削減 | 成果ベース（削減額の％） |
| 4 | 仕入〜決済の取引基盤 | 取引手数料（最大） |

---

## 4. いま取り組むこと（フェーズ1の完遂）

**方針: まず棚卸高速化の機能を徹底的に固める。** その過程で「正確なデータ蓄積」を強化し、
フェーズ2〜3の土台（質の高い時系列データ）を貯める。

### フェーズ1で固めるもの
- 音声・テキスト・バーコード・CSVなど **多様な捕捉手段**（原則4の布石）
- 複数端末リアルタイム同期・競合解決（記録の正の信頼性）
- 履歴・監査ログ（時系列データの蓄積＝フェーズ3の燃料）
- 無料/PRO のプラン基盤

### フェーズ1→2の橋渡し（土台先行）
- **E0: サーバー側プラン管理** — `isPro()` を localStorage からサーバー判定へ。
  個人課金（Stripe）にも企業契約にも必須。`docs/enterprise-design.md` 参照。

---

## 5. データへのアプローチ（フェーズ2.5）

棚卸データを「記録」から「資産」に変える。

- **正規化された時系列**（`inventory_lines` は v2 で導入済み）= 分析・予測の基盤
- 店舗ごとの **消費ペース・廃棄・発注履歴** = 他社が取れない独自データ
- このデータが、フェーズ3のAI機能（需要予測・適正在庫）の学習・推論材料になる

> 原則: **どんな機能も「データが貯まる形」で作る。** 使い捨ての表示で終わらせない。

---

## 6. AIとの共存・AIによる機能強化（フェーズ3）

AIを「競合」でなく「機能強化のエンジン」として組み込む。

- **AIが書く/読む口を用意（MCP・API）** — 飲食店のAIアシスタントが本システムを操作・参照できる
- **意思決定支援** — 消費ペース分析 → 発注量提案 → 発注書自動生成
- **異常検知** — ロス・廃棄・盗難・棚卸ミスの検出
- **適正在庫（par level）の自動最適化**

ここで重要なのは、**AI機能の価値は蓄積データの質に比例する**こと。
だからフェーズ1〜2.5で正確なデータを貯めることが、そのままフェーズ3の競争力になる。

---

## 7. 発見性：SEO → GEO/AEO

検索（Googleでクリック）から、AIに聞く（ChatGPT/Perplexity/AI Overview が答える）へ移行。
狙うのは **「AIに引用される／AIから呼ばれる」**こと。

- 構造化データ・明快な事実コンテンツ（比較表・FAQ・機能定義）
- 第三者の比較・レビュー・導入事例に載る（AIの情報源になる）
- 「飲食店の棚卸」の決定版コンテンツを一次情報として持つ
- **製品自体をAIアクセス可能に**（MCP/公開API）= 発見されるだけでなくAIの実行先になる（原則3）
