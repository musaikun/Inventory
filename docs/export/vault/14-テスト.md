## テスト戦略
- ロジック（競合判定・マージ・認証・エンタイトルメント）→ ユニットで固定 🤖
- 実機でしか出ないもの（表示3サイズ・戻る操作・音声・オフライン復帰）→ 手動台本 🖐
- **核心リスクは「2端末同期・再接続・競合」= ユニットで再現しにくい** → E2Eスモーク1本の自動化価値が最も高い:
  `ログイン→ホスト開始→ゲスト参加→在庫反映→切断再接続→マージ確認`

## ルール
- 新機能=ユニットテスト追加＋test-checklist に手動項目追加（共通チェックリスト必須項目）
- 「テストが通った」≠「正しい」。実機確認を必ず挟む（人間が最終レビュー）
- リリース前: `npm test`（app/worker）→ プレビューURLで手動台本 → main merge
