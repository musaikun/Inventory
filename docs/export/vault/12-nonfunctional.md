# 12 非機能要件

スナップショット: 2026-07-15 / v0.48

## 目標値
| 項目 | 目標 |
|---|---|
| 音声入力の遅延 | < 500ms |
| 在庫更新の他端末反映 | < 1秒（WebSocket） |
| 対応端末 | iPhone SE2 以上・Android 同等 |
| オフライン | 入力継続可・再接続で updatedAt マージ |
| 可用性の方針 | レート制限等はフェイルオープン（守りより現場の入力を優先） |

## スケール設計（目標: 3000店舗）
| 天井 | 内容 | 対策 |
|---|---|---|
| D1 10GB | inventory_lines が最初に到達 | R2アーカイブ（指標で発火） |
| D1 書き込み量 | saveInventoryToD1 全量PUT×30秒デバウンス | 完了時＋粗い間隔へ削減 |
| DO 128KiB/キー | inventory/auditLog が単一キー | 品目数のサーバー側上限＋超過通知 |
| Workers サブリクエスト | cron直列プッシュ送信 | バッチ化→将来Queues |
| 前提 | Workers Paid プラン（無料は書込10万/日で不足） | 課金開始時に移行 |

## 現状の空白（Wave 2.5 で埋める）
- **バックアップ**: D1 Time Travel(30日)のみ → cron→R2日次エクスポート＋リストア検証
- **監視**: console.error のみ → Logpush/Sentry で店舗単位の失敗を可視化
- **障害対応**: runbook・ステータスページなし → [24 運用・障害対応](24-operations.md)

## 記録すること（今後）
- 実測値（同期遅延・D1使用量・店舗数）を四半期ごとに記録 → 天井対策の発火判断
