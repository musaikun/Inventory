# 08 AI設計

スナップショット: 2026-07-15 / v0.48（正: `docs/strategy-10yr.md`）
状態: **方針確定・実装は保留（フェーズ3）** — データが貯まってから着手

## 核となる原則
> **「もしAIがすでにデータを持っていたら、我々はまだ必要か？」** で機能を選別する。
> 物理現実の捕捉点（棚の前で数える・発注する・納品を受ける）を押さえ、
> **記録の正**になり、AIの競合ではなく**手足**になる。

## フェーズ3で想定する機能
- AI発注（消費 = 月初在庫 + 入庫 − 月末在庫 の環は v0.48 で完成済み＝燃料収集中）
- ロス検知（理論在庫とのズレ＝未記録の使用/入庫漏れの示唆 → 既にズレ検出は実装済み）
- 需要予測（曜日別学習は実装済み。天気タグが次の燃料）
- MCP等での外部AI連携（検討のみ）

## 着手条件
- フェーズ1完了・実データの蓄積（発注→入庫→棚卸のサイクルが複数店舗で回ること)
- 精度検証: 「甘い数字を出さない」原則（信頼度ゲート・データ不足は参考外と明示）

## AI利用のリスク管理（実装前に決めること）
- [ ] 顧客データをモデル改善・学習に使うか → **企業商談の定番質問**。プライバシーポリシーに布石を打つ
- [ ] 音声入力（Web Speech API）は音声が端末外（ベンダーサーバー）へ送られる場合がある → ポリシー記載の確認
- [ ] AI出力の誤りが発注ミス（=金銭損害）に直結 → 推奨値は必ず人の確認を挟む・信頼度表示
- [ ] 外部LLM APIを使う場合のデータ送信範囲・保持期間・DPA
