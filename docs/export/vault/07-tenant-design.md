# 07 テナント設計

スナップショット: 2026-07-15 / v0.48

## テナントキー = shopCode（店舗コード）
```
shopCode = 店舗コード = DOルームID = D1分離キー（統一設計）
```
- **D1**: 全クエリ `WHERE shop_code = ?` で分離（S-10調査で全クエリ検証済み）
- **DO**: 1店舗=1DOインスタンス。他店舗とは実行単位ごと分離（3000店に線形スケール）
- **localStorage**: `_data_owner` マーカーでアカウント切替時に前店舗の業務データを全消去（S-10対応）

## 店舗内のロール
| ロール | 権限 |
|---|---|
| ホスト | 全権（セッション開始/完了・品目リスト・単価閲覧・承認・解散）。1端末制限（単一トークン） |
| ゲスト | 入力のみ。**単価・原価は見せない方針**（WS経路のサニタイズが残課題 S-G） |

## テナント境界の守り（実装ルール）
- 新機能のD1クエリは必ず shop_code 条件（共通チェックリスト項目）
- 別店舗コードでのアクセス確認（404/403）をテストに含める
- ルーム参加はその回のセッションIDが鍵（ルーム限定URL・永久パス問題は解消済み）
