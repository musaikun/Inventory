# ルーム限定URL ＋ 完了後ゲスト閲覧 設計

最終更新: 2026-10-02
ステータス: 第1段（参加のアクセス制御）・第2段（完了後ゲスト閲覧）ともに実装済み
役割: 実装時の設計記録。現在仕様は`sync-spec.md`と現行code/testを参照。

## 目的
- 招待URLを「そのルーム（その回の棚卸）限り」にする。過去のURL/店舗コードで
  別ルームに入れる“永久パス”問題を解消する。
- 完了後は同じURLで、その棚卸の結果（全体）をゲストが閲覧できる。
- 品目写真は現行の共有snapshot/resultに含めず、共有画面には表示しない。
- 閲覧可能期間 = 対象の完了から3日間。後続の棚卸が完了しても、そのURLは3日間の範囲で有効。

## URLの一生
```
①棚卸中    URL → ライブルームに参加して入力
②完了後    同URL → その棚卸の結果を読み取り専用で閲覧
③期間経過  同URL → 「閲覧期間が終了しました」
```
- 各URLは「その回のセッションID」を鍵に持つため、棚卸ごとに別物。
- 完了から3日で自動失効する。新しい棚卸の完了だけでは失効しない。

## URL形式
`?store=<店舗コード>&s=<セッションID>`
- 店舗コード = DO ルームのルーティング用（従来どおり）
- s = その回のセッションID（鍵）

## 第1段：参加のアクセス制御
- `getShareUrl()` に `&s=<sessionId>` を付与。
- ゲスト参加WSの join に `joinSessionId` を載せる。
- RoomDO のゲスト join: 保存中 sessionId が空でなければ
  `joinSessionId === sessionId` を要求。不一致は `invalid_link` で拒否。
- **店舗コードの手入力参加は廃止**（LandingPage のコード入力欄を削除、QR/リンクのみ）。
- 再接続（同一アクティブセッション）の間は同じURLが有効。新規セッション開始で旧URL失効。

## 第2段：完了後ゲスト閲覧 ✅ 実装済み
実装メモ:
- バックエンド: `GET /room/:code/result?s=<sessionId>`（`worker/src/storeHandler.js` の `handleRoomResult`）。
  無認証・IPレート制限あり。完了済みのsnapshotがあり、完了から3日以内のときだけ返す。
  単価・小計・在庫金額・参加者合計を含む（2026-09-30 User判断）。共有URLを受け取った人は
  店舗の在庫金額まで閲覧できるため、URLを公開範囲そのものとして扱う。
- フロント: `?store=CODE&s=SID` でアクセス → `fetchRoomStatus` でライブ判定 →
  アクティブなら参加、非アクティブなら `fetchRoomResult` で結果取得 → `GuestResultView.vue`（金額を含む・編集不可）。
- 閲覧期間定数: `worker/src/constants.js` の `RESULT_WINDOW_DAYS = 3`（フロントの `CORRECTION_DAYS` と一致）。
- 共有URLは第1段の `getShareUrl()` が付与する `&s=<sessionId>` をそのまま利用する。

設計:
- データ源は D1 スナップショット（store_history）。DOは完了時に解散するため。
- 読み取り口（無認証・URLが鍵）: `GET /room/:code/result?s=<sessionId>`
  - 対象セッションの完了snapshotがあり、完了から3日以内なら返す。より新しい完了sessionの有無は問わない。
  - **金額（単価・小計・在庫金額・参加者合計）を返す**。URLを知る人へ見せてよい結果だけを共有する。
  - 返す内容: 品目・数量・単位、参加者、変更履歴（誰が・何を・いつ）。
- ゲスト導線: URLアクセス → まず参加を試行 → セッション非アクティブなら
  result エンドポイントを確認 → あれば読み取り専用ビュー、無ければ「期間終了/未開始」。
- ゲスト用の読み取り専用結果ビュー（金額を含む・編集不可・変更履歴あり）。

## 決定事項
- 完了後の共有結果では金額を見せる。進行中WebSocketのguest configでは、従来どおりpricesを送らない。
- ゲストは全体の結果を見る（自分の分だけではない）。
- 変更履歴は「誰が・何を・いつ」を含む。
