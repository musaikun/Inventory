## 2026-11-02 — version 0.187.1 / 日誌の棚卸に「進み方」を必ず出す（短い棚卸・中断なし・人ごとの入力）

User: 短く終わった棚卸（6人で24分）は、日誌のタイムラインにたたみの欄が出ず、どう進めたかが見られない。短い時間でも見られるように。
- 原因: たたみの欄は「中断が4回を超えたとき」だけ出していた。中断0回の棚卸は開始と完了の2行だけ。
- `journalRecords.crewSpans`: 変更の記録（auditLog）から人ごとに 最初と最後の入力の時刻・入れた品目の数。`stockRecords` の記録に `crew`。
- `dayTimeline`: 棚卸の区間に人ごとの行（ev: join「鈴木 48品目 / 14:44〜14:46」）を足す。
- `DayTimeline`: 中断か人の行がある棚卸は、開始の下に必ず「進み方 ・ N人 ・ 中断 N回（時間）/ 中断なし」。中断が4回を超えるか2人以上ならはじめは閉じる。1人・中断4回までは従来どおり開いたまま。
- 検証: app vitest 2191 pass（JournalPage に短い6人の棚卸と1人の棚卸のテストを追加）・build OK・ハーネスで6人・280品目の棚卸の日誌を目視（たたみ→開くと6人の行）。

## 2026-11-01 — version 0.185.0 / 発注: 前回の棚卸は2日以内だけ選んで参考に・破棄した棚卸の数が在庫欄に入る

User: 発注を始めると一覧の在庫欄に直前の棚卸の数が入る（破棄した棚卸の数まで）。日が経つと当てにならないので、棚卸から2日以内のときだけ使うか選べるように。
- 在庫欄に入る経路は特定できず（開始時は reset() している）。後から入る入口を2つ塞いだ: ① D1 の進行中在庫は sessionId が今のセッションと一致するときだけ取り込む（不明・欠落も入れない）② ルームから届く在庫は、ルームの種類（棚卸／発注）が今のセッションと同じときだけ受ける。**再発したら別経路**。
- 前回の棚卸の持ち込み: 発注の開始時、最新の完了済みスナップショット（破棄は履歴に無い）が保存から48時間以内なら confirm で訊く。入れたら `carriedStock`（`order_carry_<orderId>`）に持ち、一覧の在庫欄に「前回 N」を薄く（確認済みには数えない）、OrderSheet に「前回の棚卸 N（M/D）」、推奨の計算の在庫に使う（この発注で数えた在庫が優先）。再開時は保存から戻し、訊き直さない。
- 検証: app vitest 2188 pass・build OK。実機未確認。
- version: 0.184.0 → **0.185.0**。
