## 2026-10-09 セキュリティイベントの構造化log（Claude Code・User指示で Codex から引き取り）

- `worker/src/securityLog.js`: `{"evt":"security","type":...}` の1行 JSON を `console.warn` で出す。
  残す項目は allowlist（shop / ip / kind / path / method / status / code / missing / role / reason）だけ。
  トークン・PIN・本文・ヘッダは渡されても書かない。IP は IPv4 /24・IPv6 /48 まで残して伏せる。
- `worker/wrangler.toml` に `[observability] enabled = true / head_sampling_rate = 1` を明示（Dashboard で有効化済みの設定を deploy で上書きしないため）。
- テスト: `src/securityLog.test.js`（masking・allowlist）、`test/securityEvents.test.js`（router が出すこと）。

### 出す event と警報の目安（Workers Logs で `evt = security` と `type` で絞る）

| type | いつ | 主な項目 | 警報の目安（案） |
|---|---|---|---|
| `login_failed` / `staff_login_failed` | PIN・暗証番号の誤り | shop, ip | 同じ shop で1時間に20件以上（締め出しを繰り返されている） |
| `login_lock_started` | 鍵の無い端末の失敗が上限に達した瞬間（店主・管理者の端末へプッシュ通知も送る） | shop, ip | 店舗側へは通知済み。運営は同じ shop で1日3件以上なら調べる |
| `login_locked` / `staff_login_locked` | 失敗上限で 429（2026-10-09 から信頼済み端末は別に数える） | shop, ip | 1時間に20件以上（止まっていても試し続けている） |
| `ip_attempt` | IP 単位の計上（login / probe / register） | ip, kind | probe が1時間に全体で300件以上（店舗コードの総当たり） |
| `ip_blocked` | IP 単位の上限に当たった | ip, kind | kind=register が1日に3件以上（店の量産） |
| `perm_denied` | 役割の権限で 403 | shop, role, missing, path | 同じ shop で1日に20件以上（API の直接呼び出し） |
| `snapshot_locked` | 確定済みの履歴の書き換えを 409 | shop | 端末の競合でも出る。急増したら調べる |
| `room_host_auth_failed` | ルームのホスト権限を拒否 | shop, reason | 同じ shop で1時間に10件以上（乗っ取りの試み） |
| `internal_error` | 想定外の例外で 500 | method, path | 1時間に10件以上（障害） |

### 残り（User判断）

- 警報の通知先と仕組み。Workers Logs（Free・保持3日）は検索はできるが、ログの条件で通知する機能は
  有料側。Free のまま行くなら「毎朝 Dashboard で上の条件を見る」運用か、Worker の日次 cron で集計して
  通知する実装（別タスク）のどちらかを決める。
- 公開文面（privacy）: Workers Logs に「伏せた IP・店舗コード・操作の種類」が最大3日残ることを書く。
- 互換日（`compatibility_date = 2025-01-01`）の段階更新は未着手。
