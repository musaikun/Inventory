# SEC-005 — 無制限な店舗作成経路を整理

- 状態の正本は [`../task-list.md`](../task-list.md)

- 根拠: `/auth/register` と `worker/src/index.js:118-121` の legacy `/store/create` に、
  濫用防止と明確な廃止条件がない。
- 2026-10-08（Claude Code・User依頼のセキュリティ確認から）: legacy `/store/create` を廃止した
  （route・`handleStoreCreate`・App の未使用 `createStore` を削除、404 をテスト）。
  **残りは登録の rate limit / bot 対策**。状態・担当は task-list のまま。
- 2026-10-08（Claude Code・User指示で Codex から引き取り）: `/auth/register` に IP ごとのレート制限
  （1時間に5回・成否を問わず計上・超過は 429 `rate_limited`）。`ip_attempts` の kind `register`、
  窓と上限は `constants.js` の `REGISTER_WINDOW_MS` / `REGISTER_MAX_PER_IP`。保持期間もこの窓を含める。
  店舗コードの乱数を `Math.random` から `crypto.getRandomValues`（棄却で偏りなし）へ。
  テスト: `index.test.js`（5回目まで通り6回目が429、失敗も計上、別IPは通る）、`rateLimiter.test.js`、`workerUtils.test.js`。
  **残り（User判断）**: bot 対策（Cloudflare Turnstile 等は site key と画面の追加が要る）を入れるか。
  同じ回線の店（例: モール内の複数店舗）が1時間に6店以上登録する運用は想定していない。
- 完了条件:
  - legacy 経路を廃止または明示的に保護する。
  - 登録の rate limit と bot 対策方針を決める。
  - 正常登録、過剰試行、legacy 呼び出しをテストする。
