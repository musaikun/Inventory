## 背景

デスクトップ用ブレークポイントが実質存在しなかった。
`@media (min-width: ...)` は `app/src/components/AxisAssignModal.vue:478` の1箇所のみで、
`#app` は `max-width: 600px` 固定。PCでは細い縦帯＋左右のグレー余白になり、
`:hover` もほぼ無いためマウス操作の手応えが無かった。

Web/PWA Free版を公開する以上PCからの到達は発生するが、
`WEB-01`〜`WEB-10` のどのgateにも本項目は無い。**gate入りの可否はPM判断待ち**。

設計上の制約として置いたもの:

- **モバイル表示は非改変**。デスクトップ規則はすべて `@media (min-width: 1024px)` かつ
  `body.dt-shell` 配下に閉じ込め、既存のモバイルCSSは編集していない。
- **App.vueのテンプレート再構成をしない**。`#app` をグリッド化すると650行のテンプレート全体を
  ラッパで囲む必要があり、Codex作業と広く衝突する。サイドナビを `position: fixed`、
  逃げ幅を `body { padding-left }` で作って回避した。
- 閾値 1024px は `useMediaQuery.js` の `DESKTOP_QUERY` と `style.css` の
  メディアクエリに二重定義されている（メディアクエリはcustom propertyを読めないため）。**対で保つこと**。
- **端末種別（PC/タブレット/スマホ）は判定しない**。iPadOS Safariは既定で自分を
  Macintoshと名乗るためUAでは区別できず、`navigator.userAgentData.mobile` はChromium限定。
  判定したいのは結局「どれだけ場所があるか（幅）」と「入力が精密か（pointer/hover）」の2軸なので、
  レイアウトは `min-width`、操作フィードバックは `hover` / `pointer` で分ける。
  既存の `AxisAssignModal.vue:477`（PC・タブレットを`min-width:700px`で束ねる）と同じ方針。

### レイアウトの分岐方針

**変えてよいのはレイアウトだけ。挙動と機能は分岐させない。**
同じデータ・同じ操作が幅に応じて並び替わるのは健全だが、「PC版だけこの機能がある」は
UIが2つになり、テストとサポートが二重化するため入れない。

- ~~セッションタブ（トラック1枚目）はデスクトップで**2列グリッド**に組む~~
  → **2026-08-08（S8）で書き換えた**。下記「2列グリッドの適用範囲を絞った」を参照。
- 履歴タブ（2枚目）は履歴カレンダーが主役でグリッド化すると崩れるため対象外。760px中央寄せのまま。
- `(pointer: coarse)` のときサイドナビ下部の設定・フィードバックを44px以上へ広げる
  （横向きタブレットは幅の条件を満たすが指で操作するため）。**この分岐は S8 でも維持している**。

### 2列グリッドの適用範囲を絞った（2026-08-08 / S8）

`eb99895` は**セッションタブ全体**を2列グリッドにしていた。当時の中身が
「データ管理 / 棚卸 / 入出庫 / 発注 / スケジュール」という**並列のカード列**だったため妥当だったが、
S8 でこのタブを「① 品目を準備 → ② 棚卸をする → ③ 記録を見る」の**順路**に組み直した。
順路の各段が横に割れると読む順序が失われるため、grid の対象を `.beta-group`
（入出庫 / 発注 / スケジュール＝ここだけが並列の選択肢）に縮小した。

- 順路（`.flow-step` + データ管理 + 棚卸hero + 履歴導線）は**縦一列**。既存の 760px 中央寄せに乗る
- `.beta-group` のみ2列。`.move-wrap` の高さ揃え（内側ボタンを `flex:1` で追従）は**そのまま移設**
- 進行中の発注カード（`.order-live`）は情報量が多く隣と釣り合わないため全幅へ戻す
- `eb99895` の `(pointer: coarse)` タップ領域確保は**残している**（書き換え対象は grid 部分のみ）
