## 調査（2026-10-12・develop 8e37bae 時点・App.vue 4898行）

`// ──` の見出しで区切らず、script を AST（@babel/parser）で読み、節ごとに「他の節の宣言を何個参照し、
どの状態を書き換えるか」を測った。

- **見出しと中身が合っていない**。「あとで数える フラグの切替」の下（約460行）の実体は useSync の
  コールバック約25個の配線と onMounted。「ルーム参加前の名前設定」の下（約270行）にログイン・開始・履歴同期、
  「発注数の同期」の下に確認モーダルの `onConfirm` / `onCancelConfirm` / `onEditSave` がある。見出し単位では分けない。
- **共有の中心が2つ**。画面管理（`currentView` ほか）は16節が参照し、`currentView` を書き換える節は6つ。
  `showToast` は16節が参照。
- **戻るボタン制御（`_closeTopLayer`）は全モーダルを知っている**（17節を読み、13の状態を書き換える）。
  そのまま composable へ移しても結合は減らない。直すなら各層が自分の閉じ方を登録する形への設計変更。
- **依存が少ない節**: 発注の参考値（外部参照3）、トースト（0）、オンボーディング・フィードバック・レビュー促進（0〜1）、
  経過タイマー（3）、オフライン監査（3）。
- **テスト境界**: `App.*.test.js` 14本が App を実際にマウントして DOM で見る。`vi.mock` はモジュールのパスで
  差し替えるので、composable へ移してもモックは効く。上の「依存が少ない節」は App のテストで守られていない。
- **並行作業**: App.vue は 9/30〜10/02 だけで12 commit。「表がホーム」の再設計（proposals 2026-09-30）が途中で、
  セッション画面の template・入口の流れは作り直される見込み。そこは今は切り出さない。
- 気づき（未対応・挙動は変えていない）: 発注の補充目標は、App（数量入力）では学習した適正在庫を
  `orderBaseFor` に渡すが、`useStockView`（在庫タブ・品目ページ）は渡さない。画面によって目標が違いうる。
  仕様判断が要るので、この refactor では触らない。
