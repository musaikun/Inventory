# UI-003 — 振り分け画面のホイールと並べ替え動作を調整

## 範囲

- 着手日: 2026-09-01
- Userの明示依頼によるUI調整。Web release gateへの追加や、API・DB・認可・保存形式の変更は行わない。

## User報告

1. 分類先が端で止まり、一周してつながるホイールになっていない。
2. ホイール領域と品目一覧の領域が切り替わる際、サイズが急に変わって見える。
3. 分類先の管理でカードを下へ動かす際、周囲のカードが上へ詰まるアニメーションが見えない。

## 完了条件

- 分類先ホイールは先頭・末尾で止まらず、同じ並び順のまま両方向へ循環できる。
- 中央の分類先、件数、追加・削除・編集後の位置、品目の振り分け結果が循環後も一致する。
- ホイール領域の展開・縮小と補助表示が同じ時間軸で滑らかに切り替わる。
- `prefers-reduced-motion` は尊重し、動きを減らす設定では即時切り替えを維持する。
- 分類先を上・下のどちらへ並べ替えても、場所を空けるカードの移動が見える。
- 既存の品目タップ、左スワイプ非表示、戻る制御、分類先CRUDを回帰させない。
- 対象test、App全体test、production build、`git diff --check`を実行し、結果を記録する。

## 2026-09-04 実装・検証記録

### 実装

- 仮想slotを分類先数の剰余で実indexへ写像し、2件以上は先頭・末尾を両方向へ循環。0件と1件は重複カードを描画しない。
- ホイール高さ、カードの開閉、操作レール、中央マーカー、上下フェードを420msの同一時間軸へそろえた。`prefers-reduced-motion` ではホイールの回転・面積遷移を即時反映する。
- 品目操作前に中央slotへsnapし、表示中の分類先と実際の保存先がずれないようにした。Pointer Capture後のclickがstageへ移る端末は、pointerdown時のslotから選択先を復元する。
- 分類先のドラッグ中はDOMの並びとFLIP補間だけを更新し、pointerup時に1回だけ保存する。上下の移動、連続反転、`pointercancel` / `lostpointercapture`、端オートスクロールに対応した。
- ホイールと並べ替えの上下矢印キー操作、現在位置の読み上げ名、分類先管理のfocus trap・開いた元へのfocus復帰を追加した。
