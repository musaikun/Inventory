# UI-003 — 振り分け画面のホイールと並べ替え動作を調整

## 範囲

- 着手日: 2026-09-01
- Userの明示依頼によるUI調整。Web release gateへの追加や、API・DB・認可・保存形式の変更は行わない。

## User報告

1. 分類先が端で止まり、一周してつながるホイールになっていない。
2. ホイール領域と品目一覧の領域が切り替わる際、サイズが急に変わって見える。
3. 分類先の管理でカードを下へ動かす際、周囲のカードが上へ詰まるアニメーションが見えない。

### 2026-09-04 追加フィードバック

1. localhostのデスクトップ操作では感じる慣性が、スマホのホイール操作では感じられない。
2. ホイール領域の展開・収納を、現在よりゆっくり開閉してほしい。
3. 分類先の管理で、掴んだカードを1回のドラッグにつき1段しか移動できない。
4. ホイールを回す際に文字が選択され、操作が止まることがある。
5. ホイールを畳んだままでは中央の件数を押せず、「振り分け済み」を見るのに一度ホイールを
   開かないといけない。展開しなくても押せるようにしたい。
6. 面積が「1枚だけ」「3枚のホイール」「全体」の3段階ある。中間をなくして2段階にしてほしい。
7. （5の対応後）ホイールが閉じた状態で件数をタップしても、まだ振り分け済みが開かない。
8. 分類先の登録が0件のとき、その旨をホイールのある場所に表示してほしい。

## 完了条件

- 分類先ホイールは先頭・末尾で止まらず、同じ並び順のまま両方向へ循環できる。
- 中央の分類先、件数、追加・削除・編集後の位置、品目の振り分け結果が循環後も一致する。
- ホイール領域の展開・縮小と補助表示が同じ時間軸で滑らかに切り替わる。
- スマホのpointer/touch入力でも、指を離した速度に応じて自然に減速し、分類先へsnapする。
- ホイール領域の展開・収納は急に切り替わらず、内容と補助表示を含めてゆっくり開閉する。
- `prefers-reduced-motion` は尊重し、動きを減らす設定では即時切り替えを維持する。
- 分類先を上・下のどちらへ並べ替えても、場所を空けるカードの移動が見える。
- 掴んだカードは指を離すまでドラッグ状態を保ち、1回の操作で複数段を連続して移動できる。
- ホイール領域では文字選択・長押しメニュー・要素ドラッグを開始せず、回転操作を中断しない。
- ホイールを畳んだ帯の状態でも、中央カードの件数を押して振り分け済みを開ける。
- 件数を押しても帯のまま広がらず、シートを閉じた後の品目一覧の位置が変わらない。
- 畳んでいる間、中央へ重なって見えない周りのカードは押せず、意図しない分類先へ回らない。
- ホイールの面積は「帯」と「全体」の2段だけで、途中の高さで止まらない。
- 分類先が0件のとき、ホイールの場所に「まだ無いこと」と作り方が出る。
- 既存の品目タップ、左スワイプ非表示、戻る制御、分類先CRUDを回帰させない。
- 対象test、App全体test、production build、`git diff --check`を実行し、結果を記録する。

## 2026-09-04 分類先0件の案内をホイールの場所へ出す

Userの追加フィードバック8への対応。

### 実装

- 0件のときは空の円筒を見せる代わりに、**中央カードが座るはずの枠**（`left/right 16px`、
  `top 50%`、`height 56px`、`margin-top -28px`＝`.af-gcard`と同じ）へ案内を置く。
  「分類先がまだありません」と「右の『＋』で作ってください」を破線の枠で出し、
  カードが来る場所そのもので「まだ無いこと」を伝える。
  最初はホイール全面の中央寄せにしたが、Userから位置が悪いと指摘があり、カード枠へ寄せた。
- ホイールの下にあった同じ内容の`.af-empty`は重複するため削除した。
- 0件のあいだは`.af-wheel.empty`で中央マーカーと上下フェードを消す。案内の後ろに
  選択枠の線が残ると、回せば何か選べるように見えてしまう。
- 0件のときは品目一覧へ触れても帯へ畳まない。畳んでも見せる1枚が無く、案内だけが潰れる。
- 案内は`pointer-events: none`。ホイールの回転・タップ判定には一切関わらない。
- 読み上げ名は従来から`分類先は未設定です`で、見える文言と一致している。

### 検証

- 新規回帰3件: 「分類先が無いときはホイールの場所で作り方を案内する」
  「分類先が0件なら品目一覧へ触れてもホイールを畳まない」
  「分類先を1件作ると案内が消えてカードが出る」。
  既存の`.af-empty`を見ていたtestは、ホイール内の`.af-wheel-empty`を見る形へ更新した。
- 対象test: `AxisAssignFocus.groups.test.js` → **1 file / 40 tests passed**。
- 対象回帰4本 → **4 files / 71 tests passed**。
- App全体: `npm.cmd test -- --pool=threads` → **143 files / 1612 tests passed**。

## 2026-09-04 面積を2段にし、件数の押下をclickだけに頼らない

Userの追加フィードバック6・7への対応。

### 実装

- 面積の中間段を廃止した。`wheelState`は`'band' | 'open'`の2値で、`'spin'`と固定196pxの
  `WHEEL_H`を削除。`open`は従来`spin`が使っていた「画面の54%（196〜336pxで挟む）」を取る。
  回し終わりから900msで1段縮める`settleWheel()`と`_settleT`も不要になったため削除した。
  これで「回し終わってから勝手にもう一度動く」段が消え、面積は触った側でだけ変わる。
- 件数の押下を`click`だけに頼るのをやめ、`pointerdown`が件数で指がTAP_SLOP以内で
  離れたら`pointerup`の時点で開くようにした（`takeCountTap()`）。実機ではPointer Captureや
  3Dの重なりでclickのtargetがstageへ置き換わり、`isCountTap()`が成立しないことがある。
- 畳みきった帯では中央以外のカードをDOMごと描かないようにした（`fan <= 0.001`）。
  扇が閉じると周りのカードは中央と同じ3D位置へ完全に重なる。透明でも同じ場所に居ると
  手前後の判定が曖昧になり、押下が後ろのカードへ吸われうる。見えていない間は
  出さないことで、押せる相手を中央の1枚に確定させた。
- `stopWheelForControl()`は面積を動かさない`stopWheelAtNearest()`と同じ意味になったため
  廃止し、開く処理は`openAssigned()`に集約した。

### 検証

- 新規回帰3件: 「clickがstageへ置き換わっても、件数の押下で振り分け済みが開く」
  「件数を押したまま指を大きく動かして離したら開かない」
  「面積は帯と全体の2段だけで、途中の高さを取らない」（回し終わりに待っても
  途中の高さへ落ちないことを確認。旧実装は900ms後に196pxへ戻していた）。
- 既存の「畳んだままでも中央の件数を押して…」は、畳みきったカードが1枚になる仕様に合わせて更新。
- 対象test: `AxisAssignFocus.groups.test.js` → **1 file / 38 tests passed**。
- 対象回帰4本 → **4 files / 69 tests passed**。
- App全体: `npm.cmd test -- --pool=threads` → **143 files / 1610 tests passed**。
- production build → **成功**（PWA precache 17 entries / 2700.72 KiB）。既知warningのみ。
- `git diff --check` → 指摘なし。
- 実機での押下成立はU-11、2段の面積はU-12としてUser確認待ち。

## 2026-09-04 畳んだホイールから件数を押せるようにする

Userの追加フィードバック5への対応。「展開してから押す」というProgressive Disclosureを、
件数の確認に限って外した。

### 実装

- 中央カードの`pointerEvents`を扇（fan）の開き具合に連動させず常時`auto`にした。
  非中央カードは従来どおり`fan > 0.6`でのみ押せる。畳んだ帯では周りのカードが中央へ
  重なって見えないため、一律に押せるようにすると見えないカードを踏んで意図しない
  分類先へ回ってしまう。押せるのは中央の1枚だけに留めた。
- `stopWheelForControl()`は畳んでいる時に`open`へ広げない。件数を押しても帯のままで、
  シートを閉じた後に品目一覧の位置が変わらず、次に押す行を探し直さずに済む。
  この関数を使う他の入口（レールの ＋ / ⚙ / 🗑）は帯では`inert`のため、挙動は変わらない。
- 帯の中だけ件数バッジの`min-height`を44pxへ広げた。56pxの帯ではカードのタップ
  （＝ホイールを開く）と押し分けが必要になるため。開いている時の見た目は変更しない。
- `pointerdown`側は従来から件数タップで面積を変えない実装だったため変更なし。
  読み上げ名（`〜 の振り分け済みを見る`）とキーボード到達性も畳んだ状態で維持される。

### 検証

- 新規回帰: 「畳んだままでも中央の件数を押して振り分け済みを開き、ホイールは広げない」。
  扇が閉じきるまで送ったうえで、中央カードが`auto`・周りのカードが`none`であること、
  シートが開くこと、`band`と高さ56pxが保たれることを確認する。
  修正前のコードでは`expected 'none' to be 'auto'`で落ちることを確認済み。
- 対象test: `.\node_modules\.bin\vitest.cmd run src/components/AxisAssignFocus.groups.test.js --pool=threads --maxWorkers=1` → **1 file / 35 tests passed**。
- 対象回帰4本（groups / pool / swipeSurfaces / App.pageBack）→ **4 files / 66 tests passed**。
- App全体: `npm.cmd test -- --pool=threads` → **143 files / 1607 tests passed**。
- production build: `npm.cmd run build` → **成功**（492 modules、PWA precache 17 entries / 2700.79 KiB）。
  既知のVite CJS非推奨と500 kB超chunk warningのみ。
- `git diff --check` → 指摘なし（GitのLF→CRLF warningのみ）。
- 実機の押し分け（帯の中で件数とカードを誤タップしないか）は`test-checklist-new-features.md`の
  U-11としてUser確認待ち。

## 2026-09-04 スマホ慣性・開閉テンポの再調整

### 実装

- 慣性速度を最後の1回の`pointermove`だけで決めず、直近120msの移動履歴から算出するよう変更。スマホがまとめて渡す`getCoalescedEvents()`も利用し、最後の1〜2pxだけで速度が消えないようにした。
- touch入力には控えめな1.25倍の初速補正を加え、最大速度は制限したまま、指を止めてから離した場合は`pointerup`までの静止時間を含めて減速する。
- 慣性の移動量と摩擦を経過時間基準へ変更し、60Hz / 120Hz端末で減速時間と移動距離が大きく変わらないようにした。
- ホイールの高さ、カードの扇、操作レール、中央マーカー、フェードの開閉時間を420msから700msへ統一。`prefers-reduced-motion`の即時切り替えは維持した。
- 並べ替えのPointer Captureを移動するカード内のつまみから、DOM上で動かない一覧コンテナへ変更。最初の入れ替えでcaptureが失われず、指を離すまで複数段を連続して移動できるようにした。
- ホイール内へ`user-select: none`、`-webkit-user-select: none`、`-webkit-touch-callout: none`を限定適用し、`selectstart` / `dragstart`もキャンセル。文字選択や長押しメニューで回転が中断しないようにした。

## 2026-09-04 実装・検証記録
