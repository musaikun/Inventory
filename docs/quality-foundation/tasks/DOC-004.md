## 要確認2 — soft auth経路のスタッフ権限（2026-11-02 User: 照合する → 結果）

入口は店舗の認証（`verifyStoreAccess`）だけで、その先の確認は経路ごとに違う。`worker/src/index.js`を読んで照合した。

| 経路 | 金額の秘匿 | 権限の確認 | 判定 |
|---|---|---|---|
| `GET /config` | ✓ 単価を落とす（`moneyGuard`） | — | OK |
| `PUT /config` | ✓ 単価は前の値に戻す | ✓ 変えた中身で要る権限（`configChangePerms`） | OK |
| `GET /history` | ✓ 金額を落とす | ✗ `report`を見ない | **gap**: レポート権限のないスタッフもAPIでは過去の棚卸（数量）を読める。画面ではタブを隠しているだけ |
| `POST /history`（訂正・ロック） | ✓ 金額は前の値に戻す | ✗ なし | **gap**: ログインしていれば誰でも完了済みの棚卸を書き換えられる |
| `DELETE /history`・`/orders/:id`・`/movements/:id` | — | ✓ `stock.discard` | OK |
| `GET/POST /orders` | 単価を持たない | ✗ POSTに`order.finish`なし | **gap**（在庫管理をオフにしたスタッフだけが対象） |
| `GET/POST /movements` | 単価を持たない | ✗ POSTに`move`なし | **gap**（同上）。「誰が」はserverが本人で上書きする |
| `GET/PUT /inventory` | 単価を持たない（進行中の数量だけ） | ✗ PUTに`count`なし | **gap**（同上） |
| `PUT /room` | — | ✗ なし | 小（active roomの更新だけ） |
| `/sessions/*`・`/imports/*`・`/images` | ✓ linesは金額を落とす | ✓ start/finish/discard/item.admin/item.edit | OK |

その他: 招待tokenは192 bitの乱数でhashだけを保存し、期限つき・1回限り。PINのない古い店舗はオーナーと同じ扱い（設計どおり）。

### 修正（2026-11-02 User: OK → D-032・実装済み）

| 経路 | 要求する権限 |
|---|---|
| `GET /history` | `report` **または** `count`。`report`だけにすると、既定のスタッフ（在庫管理＋タスク管理）の在庫ページ・日誌（直近の棚卸の数）が空になるため |
| `POST /history`（訂正・ロック） | `stock.finish` |
| `PUT /inventory` | `count` |
| `POST /orders` | `order.draft`（発注数の入力中から保存するため。`order.finish`だと入力の途中で断られる） |
| `POST /movements` | `move` **または** `item.admin`（納品の取り込みから入るため） |
| `PUT /room` | 変更なし（ルームに入った端末も呼ぶため） |

- App: 保存キューが403を「認証切れ」と扱い、**キュー全体を止めていた**。`code`が`forbidden`系の403は、その1件だけを拒否にする
- 検証: worker 754 pass（`staffRoutePerms.test.js`を新規。修正前のコードで2件失敗することを確認）、
  `staffMoney.test.js`の3件を新しい仕様へ書き換え。app 2196 pass・build OK
- 残り: タスク管理だけの人の端末も起動時に`GET /history`を呼んで403になる（応答はnull扱いで害はないが、securityログに`perm_denied`が出る）
