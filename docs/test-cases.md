# テストケース — 飲食店棚卸管理システム

最終更新: 2026-06-08 / 自動テスト導入

## 自動テスト（Vitest）

ロジック単体は自動化済み。`cd app && npm test` で約1秒で全件検証できる。

```bash
cd app
npm test          # 1回実行
npm run test:watch  # 保存のたび再実行
```

| テストファイル | 対象 | カバーするケースID |
|---|---|---|
| `worker/src/authHandler.test.js` | 認証・トークン | O-01, O-02, O-03 ほか |
| `app/src/composables/useInventory.test.js` | 在庫CRUD・localEntry・undo | S-01, C-06 の前提ロジック |
| `app/src/composables/useSync.conflict.test.js` | 競合判定 `classifyIncomingUpdate` | C-01, C-05, C-06 の判定部 |

各ケースの末尾ラベル: 🤖=自動テスト済 / 🟡=判定部のみ自動 / 🖐=手動（実機・実WS）

## 端末準備

| 記号 | 役割 | 用意するもの |
|---|---|---|
| **A** | ホスト | スマホ or ブラウザ① |
| **B** | ゲスト | スマホ or ブラウザ②（別端末 or シークレットウィンドウ） |
| **C** | 2人目ゲスト | 競合テスト C-01 のみ使用（任意） |

> D1 は空の状態からスタート。各端末の localStorage も事前にクリア推奨（DevTools → Application → Clear site data）。

凡例: ✅=期待結果 / 🔁=複数端末同時操作

## 0. オンボーディング（D1リセット直後）

### O-01 店舗の新規登録 🤖
- 前提: D1 が空。Aで初回アクセス。
- 手順: 店舗コード入力 → 店名・PIN を新規設定 → 登録。
- ✅ 登録成功しホーム（セッション一覧）に遷移。
- ✅ D1 `stores` に1件作成される。

### O-02 別端末からのログイン 🤖
- 手順: B で同じ店舗コード + PIN を入力してログイン。
- ✅ ログイン成功。Aと同じ店舗データを閲覧できる。
- ✅ D1 `auth_tokens` にトークンが発行される。

### O-03 誤PINの拒否 🤖
- 手順: B で誤ったPINを入力。
- ✅ ログイン失敗のエラー表示。トークンは発行されない。

## 1. セッション間の在庫汚染（修正: 1-5 / 2-9）

### S-01 新規セッションは必ず空から始まる ★重要 🟡
- 前提: A で品目を数件入力したセッションを「完了」or「終了」。
- 手順: A で**新しいセッションを作成**。
- ✅ 在庫が**完全に空**（前セッションの数量が残っていない）。
- ✅ 品目リストは維持されるが、数量は全てゼロ／未入力。

### S-02 セッション再開は在庫が復元される 🖐
- 手順: 進行中セッションを開き直す（同一 sessionId で再開）。
- ✅ 入力済みの在庫が正しく復元される。
- ✅ S-01 の「新規」と混同されない。

### S-03 セッション切替で前セッションが混ざらない 🖐
- 手順: セッションX入力 → 一覧へ戻る → セッションY を開く → X に戻る。
- ✅ X と Y の在庫が互いに混ざらない（下書きが正しく per-session で保持）。

## 2. 残存ルーム・遅延キック（修正: 2-9 / 2-8）

### R-01 新規セッション作成で旧ルームが即解散 ★重要 🖐
- 前提: A がセッションでゲストBを参加させている状態。
- 手順: A が**新しいセッションを作成**する。
- ✅ B は**即座に**退出させられる（数十秒待たされない）。
- ✅ B 側に「セッションが終了/切替された」旨が表示。

### R-02 ログアウトで自分のルームが解散 🖐
- 前提: A がホストのルームを開いている。Bが参加中。
- 手順: A がログアウト。
- ✅ A のルームが解散され、B も退出になる。
- ✅ D1 `stores.active_room` がクリア／無効化される。

---

## 3. オフライン復帰（修正: 4-1）

### N-01 一時オフライン → 復帰で再接続できる ★重要 🖐
- 前提: A がホストで入室中。
- 手順: A の通信を一時OFF（機内モード数秒）→ ON に戻す。
- ✅ 認証ループに陥らず、自動でルームへ再接続。
- ✅ hostToken が再検証 or 再発行され、ホスト権限を維持。
- ✅ 在庫データが失われない。

### N-02 ゲストのオフライン復帰 🖐
- 手順: B（ゲスト）を一時オフライン → 復帰。
- ✅ 自動再参加し、ホストの最新在庫に同期される。

## 4. 下書きキーの蓄積（修正: 1-8）

### D-01 セッション削除で下書きが消える 🖐
- 前提: いくつかセッションを作成し下書き入力。
- 手順: セッションを削除。
- ✅ 該当セッションの localStorage 下書きキーが削除される（DevTools で確認、キーが残らない）。

## 5. 退室中ホストへのライブ品目数表示（修正: 2-4）

### L-01 ホスト退室中もゲストの入力件数が見える ★重要 🖐
- 前提: A がホスト。B が参加して入力中。
- 手順: A がセッション画面から一覧へ戻る（ルームには残る）。
- ✅ 一覧のセッション行に、B の入力で増えていく**品目数がライブ更新**される（最大5秒間隔）。
- 手順: B がさらに数件入力。
- ✅ A の一覧の件数が追従して増える。

## 6. 同時入力の競合解決（修正: 6-1）★今回の目玉

### C-01 3秒以内の同時入力で解決バナーが出る 🔁 🟡
- 前提: A・B が同じセッション・ルームに参加。
- 手順: A と B が**同じ品目**を**ほぼ同時（3秒以内）**に別の数量で入力。
  - 例: 「玉ねぎ」を A=5箱 / B=3箱。
- ✅ 入力した**両端末**に競合解決バナーが表示される。
- ✅ バナーに「合計 8箱 / 自分 / 相手」の3択ボタンが出る。

### C-02 「合計」で解決 🖐
- 手順: C-01 のバナーで「合計」を選択。
- ✅ 数量が合算値（8箱）に確定し、相手にも反映される。

### C-03 「自分」「相手」で解決 🖐
- 手順: 別の品目で同時入力 →「自分」を選択。
- ✅ 自分の値が採用される。「相手」選択時は相手の値が採用される。

### C-04 ホストへの競合通知 🖐
- 前提: A=ホスト、B=ゲスト。B が C と同時入力で競合発生。
- ✅ ホストA に「○○: 「品目」で同時入力が発生しました」のポップアップ通知が出る。

### C-05 時間差入力は競合扱いにならない 🟡
- 手順: A が入力 → **3秒以上空けて** B が同じ品目を上書き。
- ✅ 解決バナーは出ず、トースト通知のみ。相手の値が適用される。

### C-06 未入力品目への入力は競合にならない 🟡
- 手順: A が未入力の品目に、B が初めて入力。
- ✅ 通常の更新トーストのみ。バナーは出ない。

## 7. 基本同期（リグレッション確認）

### B-01 在庫のリアルタイム同期 🖐
- 手順: A が入力 → B の画面。
- ✅ B に即時反映（更新トースト）。

### B-02 完了状態の同期 🖐
- 手順: A がホストで「棚卸完了」。
- ✅ B が強制退出 or 完了画面に遷移。ルームが閉じる。

### B-03 チャット 🖐
- 手順: A→B、B→A でメッセージ送信。
- ✅ 双方向で届く。未読バッジが正しく動作。

### B-04 CSV/設定の同期 🖐
- 手順: A が品目リストを変更。
- ✅ B に品目リストが反映される。
