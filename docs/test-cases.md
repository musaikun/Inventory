## 自動テストとの境界

自動testの実行範囲は次を正とします。

- App: `app/package.json`の`npm test`と`app/vitest.config.js`。現行includeは`src/**/*.test.js`
- Worker: `worker/package.json`の`npm test`。Appとは別packageとして実行
- Build: `app/package.json`の`npm run build`

```bash
npm --prefix worker test
npm --prefix app test
npm --prefix app run build
```

上記はVitestとproduction buildの検証です。実browser、remote Worker/D1、複数端末の実WebSocketを通す
critical E2Eや、公開URLのproduction smokeを代替しません。これらは現在
`WEB-09` / `WEB-10`の未完gateです。

下表は本書の手動ケースIDと対応する代表的なテストファイル（全ファイル一覧はソース参照）:

## 0. オンボーディング（D1リセット直後）

### O-01 店舗の新規登録 🤖
- 前提: D1 が空。Aで初回アクセス。
- 手順: 店舗コード入力 → 店名・PIN を新規設定 → 登録。
- ✅ 登録成功しホーム（セッション一覧）に遷移。
- ✅ D1 `stores` に1件作成される。

### O-02 別端末からのログイン 🤖
- 手順: B で同じ店舗コード + PIN を入力してログイン。
- ✅ ログイン成功。Aと同じ店舗データを閲覧できる。
- ✅ D1 `auth_tokens` にトークンが発行される。

### O-03 誤PINの拒否 🤖
- 手順: B で誤ったPINを入力。
- ✅ ログイン失敗のエラー表示。トークンは発行されない。

## 1. セッション間の在庫汚染（修正: 1-5 / 2-9）

### S-01 新規セッションは必ず空から始まる ★重要 🟡
- 前提: A で品目を数件入力したセッションを「完了」or「終了」。
- 手順: A で**新しいセッションを作成**。
- ✅ 在庫が**完全に空**（前セッションの数量が残っていない）。
- ✅ 品目リストは維持されるが、数量は全てゼロ／未入力。

### S-02 セッション再開は在庫が復元される 🖐
- 手順: 進行中セッションを開き直す（同一 sessionId で再開）。
- ✅ 入力済みの在庫が正しく復元される。
- ✅ S-01 の「新規」と混同されない。

### S-03 セッション切替で前セッションが混ざらない 🖐
- 手順: セッションX入力 → 一覧へ戻る → セッションY を開く → X に戻る。
- ✅ X と Y の在庫が互いに混ざらない（下書きが正しく per-session で保持）。

## 2. 残存ルーム・遅延キック（修正: 2-9 / 2-8）

### R-01 新規セッション作成で旧ルームが即解散 ★重要 🖐

- ✅ A のルームが解散され、B も退出になる。
- ✅ D1 `stores.active_room` がクリア／無効化される。

### N-01 一時オフライン → 復帰で再接続できる ★重要 🖐

## 4. セッションの破棄・復元

### D-01 進行中の破棄を24時間以内に復元できる ★重要 🖐
- 前提: 棚卸を開始し、数量・変更履歴・稼働時間を入力する。
- 手順: ☰から破棄し、ホームの「破棄した棚卸」から元に戻す。
- ✅ 中断中へ戻り、入力した数量・変更履歴・稼働時間が復元される。
- ✅ 破棄前のlocal下書きが無い別端末からでも、serverに預けた下書きを使って復元できる。

### D-02 24時間を過ぎた破棄は完全削除される 🤖🖐
- 手順: 期限切れ時刻を作り、破棄一覧を取得する。
- ✅ 一覧に出ず、session・明細・snapshot・取込台帳・完了claim・audit・破棄下書きが同じ店舗内で削除される。
- ✅ 別店舗の同名・同ID相当データには触れない。

### D-03 同じ種類の別sessionが進行中なら復元できない 🖐
- 前提: 棚卸Aを破棄後、棚卸Bを開始する。
- 手順: Aを元に戻す。
- ✅ 競合理由を表示して復元せず、AとBのどちらも黙って上書きしない。

### D-04 完了済み記録は古い「中断中」表示からも削除できない ★重要 🔁
- 前提: 端末Aに古い中断中表示を残し、端末Bで同じsessionを完了する。
- 手順: Aから破棄を実行する。
- ✅ serverが409 `session_completed`で拒否し、完了履歴・明細・共有結果が残る。

## 6. 同時入力の競合解決（修正: 6-1）★今回の目玉

### C-01 3秒以内の同時入力で解決バナーが出る 🔁 🟡
- 前提: A・B が同じセッション・ルームに参加。
- 手順: A と B が**同じ品目**を**ほぼ同時（3秒以内）**に別の数量で入力。
  - 例: 「玉ねぎ」を A=5箱 / B=3箱。
- ✅ 入力した**両端末**に競合解決バナーが表示される。
- ✅ バナーに「合計 8箱 / 自分 / 相手」の3択ボタンが出る。

### C-02 「合計」で解決 🖐
- 手順: C-01 のバナーで「合計」を選択。
- ✅ 数量が合算値（8箱）に確定し、相手にも反映される。

### C-03 「自分」「相手」で解決 🖐
- 手順: 別の品目で同時入力 →「自分」を選択。
- ✅ 自分の値が採用される。「相手」選択時は相手の値が採用される。

### C-04 ホストへの競合通知 🖐
- 前提: A=ホスト、B=ゲスト。B が C と同時入力で競合発生。
- ✅ ホストA に「○○: 「品目」で同時入力が発生しました」のポップアップ通知が出る。

### C-05 時間差入力は競合扱いにならない 🟡
- 手順: A が入力 → **3秒以上空けて** B が同じ品目を上書き。
- ✅ 解決バナーは出ず、トースト通知のみ。相手の値が適用される。

### C-06 未入力品目への入力は競合にならない 🟡
- 手順: A が未入力の品目に、B が初めて入力。
- ✅ 通常の更新トーストのみ。バナーは出ない。

## 8. 現行ホームと共有結果

### U-01 下部ナビ3項目と作業中の非表示 🖐
- ✅ 通常ホームで「在庫／レポート／管理」の3項目が表示される。
- ✅ レポート先頭から履歴カレンダーを開け、その下に在庫分析が表示される。
- ✅ 管理から品目管理・発注基準・取込/書出しへ到達できる。
- ✅ 棚卸中・発注中・取込途中は下部ナビが表示されず、作業状態を壊すタブ移動ができない。

### G-01 共有URLは金額を含む読み取り専用結果を3日間表示する ★重要 🖐
- 前提: 単価、数量、担当者、変更履歴を含む棚卸を完了し、共有URLを未ログインbrowserで開く。
- ✅ 品目、数量、単価、小計、合計金額、参加者別入力、変更履歴が表示される。
- ✅ 編集操作は無く、店舗の他sessionや設定へ移動できない。
- ✅ URLのsession UUIDを別店舗・不在IDへ変えてもデータを取得できない。
- ✅ 完了から3日を過ぎると410となる。

### P-01 品目写真の保存・同期・削除 🖐
- 前提: R2 bindingを持つWorkerへ同じ店舗のA/Bがログインしている。
- ✅ Aが写真を付けると、端末で圧縮された一覧用・拡大用画像が保存され、品目表の丸い画像と拡大表示に反映される。
- ✅ Bへ`config.images`が同期され、同じ画像を表示できる。写真のない品目は`no image`となる。
- ✅ 写真の差替え・削除が表示へ反映され、別店舗Bearerではupload/deleteできない。
- ✅ アカウント削除後はその店舗prefixのR2画像を取得できない。
- ✅ 共有結果には現在写真が表示されず、写真URLを知る人だけが認証なしで画像を取得できる境界を確認する。
